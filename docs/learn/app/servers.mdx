# Three servers, one interface

<OneSentence>Each kind of server is one package that turns its own API into the same Go interface, `servers.Server`; the app only ever sees that interface, and only the two programs know which package is behind it.</OneSentence>

Inkshelf reads from three very different <Term id="server">servers</Term>. Komga serves comics
as JSON and page images. Mealie serves recipes, which have no pages at all. Calibre-Web serves
ebooks through Atom feeds. Yet the app shows all three with the same screens: a list of series,
the books of a series, a book to read.

This chapter shows how. The constraint behind it: the app should not grow a branch for each
server. A fourth kind of server (and a Kobo port, one day) must not touch the screens.

<Analogy icon="🔌">Travel adapters. Every country has its own socket, but your charger has one
plug. Each adapter does the translation on its side; the charger never learns where it is.</Analogy>

## One interface and a neutral model

What the app needs from any server fits in one Go interface:

```go title="internal/servers/server.go (trimmed)"
type Server interface {
	Series(ctx) ([]Series, error)                       // sorted by title
	Libraries(ctx) ([]Library, error)
	Books(ctx, seriesID) ([]Book, error)                // in series order
	InProgress(ctx, count) ([]Book, error)              // last read first
	OpenBook(ctx, bookID, pageCount) (Pages, error)     // a book of page images
	OpenFile(ctx, bookID) (io.ReadCloser, int64, error) // a CBZ or an EPUB, whole
	SetProgress(ctx, bookID, page, completed) error
	// … FirstPage, SeriesThumbnail, BookThumbnail, ClearProgress
}
```

Its types are **neutral**: a `Series` has a title and counts of books read; a `Book` has a
number in its series, a page count and a `Format`. The format says how the book travels:

- `PageImages`: page by page, through `OpenBook`, each page a JPEG, PNG or WebP;
- `ComicArchive`: a CBZ, a zip of page images, fetched whole by `OpenFile`;
- `Reflowable`: an <Term id="epub" />, fetched whole and laid out while reading.

A server that cannot do something does not pretend. It returns an error wrapping
`errors.ErrUnsupported`, and the app does without: no library filter, no "continue reading" row,
progress kept on the reader alone. Never an empty list: the app would take it for "nothing
there" and, for progress, for "unread".

## Three translations

Each kind of server is one package (`servers/komga`, `servers/mealie`, `servers/calibreweb`)
with the same parts: a `Client` that speaks the server's API call by call, and a `Server`
(`adapter.go`) that turns it into `servers.Server`. Each `doc.go` explains its server.

</Figure>

- **Komga** is the closest to what the app wants. It authenticates with an `X-API-Key` header,
  answers in JSON, and sends each page as an image. It is the only kind that remembers how far
  you read: the app reads the progress with the books and sends it back with a `PATCH`
  ([Syncing reading progress](./sync.mdx)). One subtlety, `pageConversions`: Komga can convert
  any page to JPEG or PNG on the fly, but its PNG of a JPEG is much bigger, so the app asks for
  JPEG, PNG and WebP pages as they are, and the rest as PNG.
- **Mealie** is the strangest. A category becomes a series, a recipe a book. But a recipe has
  no pages, so the Mealie package makes them, **on the reader**: `recipepages.Layout` places the
  name, the photo, the ingredients and the steps on 1404 × 1872 pages, and `Render` draws each
  as a PNG. To the rest of the app, a recipe is a book of page images, like a comic. The page
  count is only known after layout, so `Books` lays out every recipe it lists and keeps the
  result (`laidOut`), so that `OpenBook` later agrees on the count.
- **Calibre-Web** is read through its <Term id="opds" /> catalog only: Atom feeds, with HTTP
  Basic auth. (Its JSON API needs a login session.) The catalog is read whole; a book's number
  in its series is found in its entry's text ("SERIES: Eragon [2.5]"). An EPUB is `Reflowable`,
  a CBZ `ComicArchive`, and a book with both is read as the EPUB. Files can be large, so they
  come through a copy of the HTTP client with no timeout (`fileClient`), watched by the
  download's <Term id="watchdog" /> instead.

## config.json and the registry

The user lists their servers in `config.json`, on the reader:

```json title="applications/inkshelf/config.json"
[
  {"name": "Manga", "type": "komga", "server": "http://nas:25600", "apiKey": "…"},
  {"name": "Cuisine", "type": "mealie", "server": "http://nas:9925", "apiKey": "…"},
  {"name": "Livres", "type": "calibreweb", "server": "http://nas:8083", "username": "…", "password": "…"}
]
```

`servers.LoadConfig` reads it, and is strict where a mistake would hurt later. The `name` is
also the folder of that server's books on the reader, so it must be a valid FAT folder name, and
two names may not differ only by case (FAT would see one folder).

Who turns `"type": "mealie"` into the Mealie package? Only `servers/registry`. Its `Opener`
switches on the type and calls the package's `NewServer`; `KindOf` gives the kind's name, logo
and words ("category" and "recipe" for Mealie, so the screens say the right thing). An empty
type means Komga, the first kind there was, and `calibre-web` is accepted for `calibreweb`.

The <Term id="registry" /> is imported only by `cmd/inkshelf` and `cmd/emulator`, which hand
`registry.Opener` to `app.New`. That is the trick that keeps `app` and `shelf` from importing any
one server ([The layer cake](/big-picture/layers) shows the `go list` command that checks it).

## Sorting titles

Every server's series and books are sorted the same way, by `servers.CompareTitles`, because a
plain string sort gets shelves wrong:

- "Tome 10" sorts before "Tome 2", since "1" comes before "2";
- "Le Trône de fer" files under L, with everything else that starts with an article;
- "Élégance" sorts after "Z", since "É" is a byte above every ASCII letter.

`CompareTitles` compares the <Term id="sort-key">sort keys</Term> instead. `SortKey` spells
apostrophes and dashes one way, drops a leading French or English article (le, la, les, l',
un, une, des, the, a, an) and folds the accents away. Then `naturalorder.Compare` compares the
keys with runs of digits as numbers. The details are French: "L'" is an article only before a
vowel or an h, and in "A la croisée des mondes" the A is a "à" without its accent, kept.

## Fake servers

You do not need a Komga server to work on Inkshelf. Each kind has a fake, in its own package:
`fakekomga`, `fakemealie` and `fakecalibreweb`. Each is an `http.Handler` that answers like the
real server, with fixed, generated content (comics with numbered pages, recipes, EPUBs that
test right-to-left text, MathML, links). The <Term id="emulator" /> starts them with `-fake` and
`-fake-type`, on local ports, and writes a matching `config.json`; the real client code then
runs against them. Because they never change, the emulator's screenshots compare byte for byte.

```sh
make emu-fake                                                            # fake Komga
make shots SCRIPT=emulator/scripts/mealie.txt EMUFLAGS="-fake-type mealie"
```

Tests that do not need HTTP use `servertest.Fake`, a `Server` in memory whose content is in its
fields and which records what it was asked (`PageRequests`, `SentProgress`).

<details>
<summary>Going deeper</summary>

- **One HTTP client.** `httpclient.New` makes the client every request goes through: a
  one-minute timeout and a few kept-alive connections per host. A response that is not 2xx
  becomes a `*httpclient.StatusError` with its code, so callers tell a 401 (wrong key) from a
  network error with `errors.As`.
- **Read status.** `servers.SeriesStatus` computes unread, reading or read from the counts, with
  the same rules as Komga's filter, so the series list filters every kind alike.
- **Adding a kind of server** is a checklist in the reference: a package with its `Client`,
  `Server`, `Kind` and logo, a fake, a `case` in both switches of the registry, an emulator script
  and its screenshots.

</details>
